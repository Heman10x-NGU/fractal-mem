# Benchmark methodology and primary sources

## Verified source contracts

Consulted on 2026-10-09:

* LoCoMo original code/data: https://github.com/snap-research/locomo . Its data/locomo10.json is a list of conversations with conversation.session_N dialogue turns and qa entries; not the invented sessions/dialogue schema in the launch proposal. Preserve dia_id evidence and session dates. Data license differs from package code: record and follow upstream license before redistribution.
* LongMemEval original code: https://github.com/xiaowu0162/LongMemEval . Cleaned data: https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned . Each question has haystack_sessions, haystack_session_ids, haystack_dates, answer_session_ids and question_id. Preserve abstention suffix and question_type. Official answer evaluation consumes question_id/hypothesis JSONL and requires an LLM judge. V2 is a separate dataset, not a synonym for cleaned LongMemEval-S.
* SQLite FTS5: https://sqlite.org/fts5.html . BM25 lower scores rank better. Column weights are configurable; its k1/b values are built-in, not freely tuned by arbitrary arguments. unicode61 plus separately indexed identifier components allows exact and decomposed code search.
* WAL: https://sqlite.org/wal.html . WAL permits concurrent readers and one writer. NORMAL mode has a power-loss durability tradeoff; process crashes and power loss are different failure models.
* Tree-sitter Python bindings: https://github.com/tree-sitter/py-tree-sitter . Use actual Language and Parser from installed grammar wheels; tests must parse real code, including syntax errors and nested definitions.
* Official MCP SDK: https://github.com/modelcontextprotocol/python-sdk and https://py.sdk.modelcontextprotocol.io/ . Pin the installed SDK API version; verify real stdio client/server transport, not only function calls.
* Gitleaks: https://github.com/gitleaks/gitleaks . Audit the actual supported signatures and licensing. A hand-written subset cannot be described as 150+ upstream rules.
* Anthropic cache accounting: https://platform.claude.com/docs/en/build-with-claude/prompt-caching . Total input is input_tokens + cache_creation_input_tokens + cache_read_input_tokens. Cache minimum, TTL, breakpoints and exact prompt content affect reuse. Capture usage responses, not invented HTTP cache headers.
* OpenAI cache accounting: https://developers.openai.com/api/docs/guides/prompt-caching . Read prompt_tokens_details.cached_tokens (Chat Completions) or input_tokens_details.cached_tokens (Responses) relative to total input. Exact common prompt prefix is necessary; it is not a universal percentage guarantee.

## Local reproducible suite

Use a temporary real SQLite database and real daemon. Log UTC time, platform, Python/dependency versions, git revision, dataset hash, settings, elapsed timings, requested/enqueued/committed/rejected events, and results. Benchmark outputs are JSON/CSV artifacts generated by the run, not manually typed tables. Run core 30,000-message sawtooth simulation and record each turn's byte size, batch count, byte common prefix and elapsed time. The 20,001-step rollback simulation is a separate independent correctness gate. Search benchmark indexes a named seeded code corpus, then queries actual identifiers, paths, error values and parent handles. Capture latency p50/p95/p99; never make elapsed milliseconds a flaky universal unit-test guarantee.

## Dataset evaluation protocol

No answer or evidence annotation is stored in memory. Ingest only timestamped dialogues, then query question text. Keep conversation/project isolation. Retrieval outputs are evaluated against evidence IDs for precision@k/recall@k and answer-bearing turn coverage; label these retrieval metrics. Natural-language question answer quality requires generated hypotheses and either official judge or explicit deterministic scoring suitable for the task. Report both evaluation method and category denominator. Abstention cases require separately reported performance. Full-context, flat retrieval, and FractalMem comparisons must use identical questions, answer models, output budgets and judge settings. Do not claim comparative superiority from synthetic fixtures.

## External dependencies and honest omissions

Local verification needs Python package downloads, not a paid account or vector database. Full dataset runs need upstream dataset downloads. Semantic compaction and model-generated answers require an explicit local model endpoint or provider API credentials. Live provider cache rates, exact billed token usage and streamed TTFT require actual provider calls and usage/stream observations. If unavailable, output null with an unmeasured reason and retain functioning local benchmarks. No credentials will be read from unrelated projects or committed. No paid benchmark run is silently enabled.
